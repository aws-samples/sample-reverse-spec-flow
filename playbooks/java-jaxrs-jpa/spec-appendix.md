# 仕様章立ての追補（java-jaxrs-jpa）

ISO/IEC/IEEE 29148 準拠の章立て（GP-8）に対する、このスタック固有の追補。
汎用テンプレート（`specs/*/_template.md`）の節では表現しきれない要素だけを扱う。

- **対象スタック**: Java / JAX-RS または Spring MVC / JPA アノテーション / 宣言的マイグレーション

## 追加すべき節（カテゴリ別）

| カテゴリ | 追加する節 | 理由（このスタックで必要になるもの） | 密度の判定基準 |
|---------|----------|--------------------------------|--------------|
| api | 認証・認可の宣言箇所 | アノテーション（`@PreAuthorize` 等）とフィルタ/インターセプタの**両方**で決まり、順序で挙動が変わる | 操作 1 つにつき「必要権限・宣言箇所の `path:line`・未宣言なら『認証のみ』と明記」 |
| api | 例外→HTTP ステータスの対応 | 例外ハンドラ（`@ExceptionHandler` / `ExceptionMapper`）が横断的に変換するため、個別 API を読んでも分からない | 例外種別ごとにステータスとレスポンス形式 |
| data | スキーマ最終状態の導出根拠 | マイグレーションは追記型履歴。`createTable` だけでは最終形にならない（DP-java-jaxrs-jpa-1） | テーブルごとに「定義箇所・後続変更・最終列構成」 |
| data | JPA 管理外テーブル | 中間表（`@JoinTable`）・別 DB（テナント管理等）は `@Table` 走査に入らない | 管理外テーブルの一覧と、それを操作するコードの `path:line` |
| behavior | トランザクション境界 | `@Transactional` の伝播設定・ロールバック条件で挙動が変わる。宣言がない箇所は既定値で動く | 境界ごとに「伝播・分離レベル・ロールバック対象例外」 |
| modules | 非同期・スケジュール実行 | `@Scheduled` / メッセージリスナは REST の分母に入らない別 EP | 起動契機・入力・失敗時挙動 |

## 記述方式の指定

同じ対象を複数の書き方で書くと横断突合ができなくなるため、方式を固定する。

- **API 操作の単位**は「HTTP メソッド ＋ パス」1 組を 1 項目とする（クラス単位でまとめない）。
- **権限は「必要権限コード」を原文どおりに書く**（意訳しない。再構築時に照合できなくする）。
- **テーブルは論理名でなく物理テーブル名で引用する**（マイグレーション定義と突合するため）。
- **行番号はテーブル/エンティティの**定義箇所**を指す**（変更履歴の途中を指さない。
  実測で data カテゴリの誤り率 41.7% の主因が行番号の陳腐化だった）。

## このスタックで静的読解が効かない箇所（SB-6 の具体化）

- **DI による実装解決**: インターフェース → 実装が設定・プロファイル・条件付き Bean で決まる。
  `@ConditionalOnProperty` 等がある場合、**どの設定値でどの実装が使われるか**を列挙する。
- **フィルタ/インターセプタの適用順序**: 宣言順・`@Order`・自動設定で決まり、
  認可の実効性がこれに依存する。
- **例外ハンドラの優先順位**: 複数のハンドラが同じ例外階層を扱う場合、どれが勝つかは静的には自明でない。
- **設定キーのバインド**: 綴り・単複・relaxed binding の差でバインドされないことがある。
  **設定クラスのフィールドと実際の設定ファイルの両方向差集合を取る**（SB-2（両方向の差集合））。
