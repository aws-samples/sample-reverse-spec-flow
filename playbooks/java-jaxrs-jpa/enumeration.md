# 列挙の独立ソース表（java-jaxrs-jpa / GP-105）

<!--
Playbook が提供する「分母の定義」。init.sh が `spec-extraction/01-code-graph/enumeration.md` へ配置する。
汎用手順書（pipeline-procedure）は「この表に従う」と抽象で書き、具体はここに置く（P6）。
下記のコマンドと件数はすべて Apache Fineract 1.15.0 で実測検証済み（2026-08-10）。
-->

- **対象スタック**: Java / JAX-RS（`@Path` アノテーション）または Spring MVC（`@RequestMapping`）/
  JPA アノテーション方式（`@Entity` / `@Table`）/ 宣言的 DB マイグレーション（Liquibase・Flyway 等）
- **適用判定**: `grep -rlE '^@Path|^@RequestMapping' <src> --include='*.java' | head` が 1 件以上ヒットする

## 独立ソース表（ノード種別ごとの分母）

| ノード種別 | 独立ソース（分母） | 全走査コマンド | 突合の等式 |
|-----------|-----------------|--------------|-----------|
| NODE-MOD | ビルド定義のモジュール宣言 | `grep -oE '<module>[^<]+' <src>/pom.xml`（Maven）/ `grep -E "^include" <src>/settings.gradle`（Gradle） | — |
| NODE-EP（REST） | **クラスレベル**の `@Path` / `@RequestMapping` | `grep -rlE '^@(Path\|RequestMapping)' <src> --include='*.java' \| grep -v '/build/' \| grep -v '/src/test/' \| wc -l` | クラスレベル宣言数 = EP-REST ノード数 |
| NODE-EP（サーブレット） | `web.xml` の `<servlet-mapping>` | `grep -c '<servlet-mapping>' <src>/**/WEB-INF/web.xml` | 件数 = EP ノード数（Spring Boot 移行済みなら 0） |
| NODE-EP（バッチ・CLI） | `main()` / スケジュール登録 / コマンドハンドラ | `grep -rlE 'public static void main\(' <src> --include='*.java' \| grep -v '/src/test/'` | — |
| NODE-BND（DB: エンティティ） | `@Table(name = "...")` | `grep -rhoE '@Table\(name *= *"[^"]+"' <src> --include='*.java' \| grep -v '/build/' \| sort -u \| wc -l` | ユニーク table 名 = BND-T ノード数 ＋ 管理外テーブル |
| NODE-BND（DB: DDL） | マイグレーション定義（`<createTable>` / `CREATE TABLE`） | `grep -rhoE '<createTable[^>]*tableName="[^"]+"' <src> --include='*.xml' \| sort -u \| wc -l` | DDL テーブル数 ＝ `@Table` 数 ＋ JPA 管理外 |
| NODE-BND（その他） | メッセージング・外部 API クライアント・ファイル I/O | `grep -rl '@JmsListener\|RestTemplate\|WebClient' <src> --include='*.java'` | — |

## 目印の系統（1 目印で数え切れるかの判定。GP-2 ルール8 / FB-9）

<!--
系統は**役割を表す型**で括る（登録手段は同一系統内の 1 経路にすぎない）。
下表は Fineract 1.15.0 の実測に基づく。系統が 1 つに見えても根拠欄は必ず埋める。
-->

| ノード種別 | 目印の系統（役割で括る。複数あれば全部列挙） | 単一系統である根拠 / 系統間の重複の扱い |
|-----------|------------------------------------|--------------------------------|
| NODE-EP | ① HTTP 要求を受ける型: JAX-RS リソース（`^@Path`）／ Spring MVC コントローラ（`^@RequestMapping`）／ サーブレット宣言（`web.xml`）② プロセス起動の型: `main()` ／ スケジュール登録 ③ 書込コマンドの型: コマンドハンドラの役割インタフェース | **3 系統以上あり単一ではない。** ①は実測で 169 ＋ 1 の併存を確認（`@Path` だけでは Spring MVC を落とす）。重複は**クラス名で `comm`** を取る（同一クラスが両方式を持つ例は 0 件だったが毎回確認する）。③は**役割インタフェースの実装で括る**——注釈だけを系統にすると、注釈を使わない登録経路（名前で直接引く分岐）が漏れる |
| NODE-BND | ① JPA 管理エンティティ（`^@Entity` の役割型。表名は `@Table`）② 関連表・副表のみの宣言（`@JoinTable` / `@SecondaryTable`）③ JPA 管理外テーブル（マイグレーション定義にのみ存在） | **3 系統。単一ではない**（実測: ②で中間表 2 件、③でテナントレジストリ 4 件が `@Table` 走査から漏れていた）。重複は**表名で `comm`** を取り、`①∪②∪③` の要素和と「マイグレーション定義の全表数」を**2 経路で突合**する |

> **分母は 2 経路で計算して突合する。**下の「分母の 2 経路突合」表が正本（機械検査あり）。
> **件数が一致しても集合が一致しているとは限らない**——実測では `@Table` リテラル 251 に対し
> spec 側 257 で、差 6 は定数参照の解決値だった。**件数差の説明だけで閉じず要素を突き合わせる。**

## 分母の 2 経路突合（GP-2 ルール8-4 / ルール9。実数は Phase 1 で埋める）

<!--
【なぜ 2 経路か】単一経路で数えた合算値は**検算できない**。系統ごとの件数を足しただけでは、
系統の定義そのものが漏れていても気づけない。**独立に計算できる別経路**と突き合わせて初めて検算される。
【件数一致 ≠ 集合一致】ルール9。要素単位で突き合わせる（`comm -3` / `diff`）。
差分が 0 件なら「0 件」と書く——空欄は「測っていない」と区別できない。
【定義は Playbook が提供・実数は解析対象ごと】下表の定義列はこのスタックの実測に基づく。
`gates.sh` の `G-ENUM-SOURCE` が定義・実数・差分の記入を検査する（`phase1` の完了条件）。
【列順の理由】**数値と差分を末尾に固めてある**。定義欄に `|` が入ると前から数えた列がずれるため、
検査は末尾から数えている。
【表の中にパイプを書かない】`\|` とエスケープしても表の解析では分割される（実測）。

-->

|-----------|------------|------------|----------|----------|--------------------------------|
| NODE-EP | 系統 ①②③ の件数の和（クラス名で重複排除してから合算） | **系統に分けず**「外部から起動されうる型」を 1 パスで一括抽出した全数 − 到達不能 | `<数値>` | `<数値>` | `<0 件 ／ 差分 N 件: 要素名を全件（理由）>` |
| NODE-BND | 系統 ①∪②∪③ の要素和（表名で重複排除） | マイグレーション定義の全表数 | `<数値>` | `<数値>` | `<0 件 ／ 差分 N 件: …（理由）>` |

## 識別子の抽出（「実装できる粒度」の突合。GP-20 ルール5 / FB-11）

<!--
出力を `01-code-graph/identifiers/<種別>.txt`（1 行 1 識別子）に保存する。
`G-IDENT` が `specs/` 本文との差集合を自分で計算する（件数一致の自己申告では代替できない）。
**実運用（Fineract）で 257 表のうち 90 表が物理表名で specs/ に一度も登場していなかった**——
エンティティの `path:line` は正確でも、物理表名が本文に無ければ DDL は書けない。
-->

| 種別（ファイル名） | 仕様本文に実在すべき識別子 | 抽出コマンド |
|-----------------|----------------------|-----------|
| `table` | **物理テーブル名**（data 仕様から DDL を書くのに必須） | `grep -rhoE '@Table\(name *= *"[^"]+"' <src> --include='*.java' \| sed 's/.*"\([^"]*\)".*/\1/' \| sort -u` |
| `table` （JPA 管理外） | マイグレーション定義にのみ存在する表名 | `grep -rhoE '<createTable[^>]*tableName="[^"]+"' <src> --include='*.xml' \| sed 's/.*tableName="\([^"]*\)".*/\1/' \| sort -u` |
| `endpoint` | **URL パス**（api 仕様に必須。パス変数は記号入りなので部分一致で救済される） | `grep -rhoE '^@Path\("[^"]*"' <src> --include='*.java' \| sed 's/^@Path("\(.*\)"/\1/' \| sort -u` |
| `entity` | エンティティのクラス名（modules / data の突合用） | `grep -rlE '^@Entity' <src> --include='*.java' \| tr '\n' '\0' \| xargs -0 -r -n1 basename \| sed 's/\.java$//' \| sort -u` |

> **`table` は 2 コマンドの出力を結合して 1 ファイルにする**（JPA 管理と管理外の両系統。「目印の系統」節を参照）。
> `gate-snippets.sh idents-table` / `idents-endpoint` で実行できる。

## 走査の落とし穴（このスタック固有。すべて実測で確認済み）

1. **`@Path` は行内任意位置で数えると過大になる。**
   実測（Fineract）: 行頭限定（クラスレベル宣言）**169** に対し、行内任意位置は **171**。
   差分 2 件は「除外対象モジュール 1 件」と「コメント内の `@Path` 文字列 1 件」。
   **宣言位置（行頭）まで固定する**（SB-2（宣言位置まで固定する））。メソッドレベルの `@Path` は EP の子であり、
   クラスと同じ単位で数えると重複する。

2. **JAX-RS と Spring MVC が同一リポジトリに併存する。**
   実測（Fineract）: `@Path` 169 件に対し `@RequestMapping` が **1 件**（`DummyApiController`）実在し、
   合計 **170**。`@Path` だけを独立ソースにすると Spring MVC 側の EP を丸ごと落とす
   （SB-2（目印 1 種類で足りると仮定しない）: 同じ役割を果たす別系統の目印を先に列挙する）。
   **本 Playbook の `gate-snippets.sh ep` は両方式を走査する**（`^@(Path|RequestMapping)`）。
   同様に、別アダプタ（Batch API・CLI・メッセージング）が存在しうるため、
   「REST の分母 = 全 EP の分母」と早合点しない。

3. **`@Table` の値が定数参照だとリテラル限定 grep で数え落とす。**
   実測（Fineract）: リテラル `@Table(name = "...")` のユニーク抽出は **251**。
   一方 spec 側の記録は **257** で、差 6 は定数参照を解決した値と推測される。
   **リテラル抽出と「`@Table` を持つクラス数」の両方を出して差を説明する**。

4. **`@JoinTable` / `@SecondaryTable` は `@Table` 走査に含まれない。**
   実測（Fineract）: 中間表 `m_appuser_role` / `m_role_permission` の 2 件が `@JoinTable` のため
   分母から漏れていた。同型で**テナントレジストリ DB の 4 テーブルが JPA 管理外**で漏れていた。
   `grep -rl '@JoinTable\|@SecondaryTable'` を別途走査する。

5. **マイグレーション定義の件数は「実行時のテーブル集合」ではない。**
   `<createTable>` を数えても、後続の `<dropTable>` / リネームで最終状態は変わる。
   さらに **どの changelog からも include されない定義ファイル**は到達不能で分母外である
   （実測: `tenant/upgrades/` は参照ゼロ＝分母に入れてはいけなかった）。
   **到達可能性を確認する**: `grep -rn '<include file=' <src> --include='*.xml'` で参照グラフを辿る。

6. **`build/` と `src/test/` を除外する。** 除外しないとビルド生成物とテストフィクスチャが混入する。

7. **seed データの投入件数と実装実体の件数は一致しない。**
   実測（Fineract）: 処理ステップの実装クラス **15** に対し、DB 投入 seed は **13 件**。
   **両方向の差分を取る**（実装のみ / seed のみ）。片側だけでは無音で落ちる（SB-2（両方向の差集合））。


### 逆引き索引の分母（`SOURCE_EXCLUDE`）

`gate-config.env` の `SOURCE_EXCLUDE`（POSIX ERE）は、逆引き索引（`GP-4` ルール7〜8）が
**引用を実ファイルへ解決するときの分母**から除くパスを決める。**Phase 0 で設定する。**

```sh
# Gradle/Maven のビルド出力とテストフィクスチャを除く（この Playbook の列挙と同じ除外にそろえる）
SOURCE_EXCLUDE='(^|/)(build|target|out)/'
```

**入れないとどうなるか**: 同名のビルド生成物が分母に入り、`web.xml` のような basename 引用が
「候補複数」で解決できなくなる。実測（Apache Roller）: 除外なしで引用の **23%（1,748/7,624）が解決不能**、
`target/` を除外して **0.9%（67 件）**。索引は 10% を超えると原因と対処を本文に書く。

**値は必ず引用符で囲む**（囲まないと `gate-config.env` が bash の構文エラーになり `gates.sh` が中断する）。

## 実行記録（Phase 1 で埋める。Phase 4 で再実行して突合する）

<!--
【「独立ソースの実数」は**集約前**の実数を書く（GP-2 ルール8-7）】
役割で束ねてノード登録する場合（例: 69 ディレクトリを 16 単位にまとめる）、
**独立ソース側には 69 を書き、ノード登録数に 16 を書く**。集約はここで差分として現れる。
集約した数をそのまま独立ソース欄に書くと差分が 0 になり、**粒度の粗さが記録から消える**
（実測: 実運用で 69→16 の集約が「16 = 16」と記録され、`G-DENOM` は PASS し続けた）。
差分に説明があるだけでは完了にしない——**完了を宣言する前に差分には ADR 参照が必要**である
（説明＝観察／ADR＝決定。決定のない粒度で完了させない。分母の粒度の処分は `G-ENUM-SOURCE` が検査する）。
