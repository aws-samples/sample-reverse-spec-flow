## DP-java-struts-ormxml-1: マッピングファイルの実体と `persistence.xml` 宣言は両方向で突合する

### 目的
`*.orm.xml` 方式では、**ファイルが存在することと JPA が読み込むことが別**である。
`persistence.xml` の `<mapping-file>` に宣言されていないファイルは無視される。
片側だけを分母にすると「宣言漏れ（実体はあるが永続化されない）」も
「宣言のみ（ファイルが無い＝起動時エラー）」も見えない（SB-2（両方向の差集合））。

**さらに突合の「キー」を間違えると、件数が合ったまま同一性が壊れる。**
`basename` で比較すると、同名ファイルが複数モジュールにある構成で別モジュールのファイルを同一視する
——差分の件数は正しいのに、差分が**どのファイルか**を誤る。
**そして「実体のみ」の差分は対処が 2 通りに分かれる**:

| 差分の種類 | 実体 | 宣言 | マップ先クラス | 正しい対処 |
|---|---|---|---|---|
| **宣言漏れ** | あり | なし | **実在する** | `persistence.xml` に宣言を足す |
| **死蔵ファイル** | あり | なし | **不在** | **ファイルを消す**（宣言を足すのは誤り） |

**区別せずに「宣言漏れ」と書くと、存在しないクラスへの参照を有効化する対処を推奨してしまう。**

### ルール
1. **両方向の差集合を取る**（宣言のみ / 実体のみ）。`gate-snippets.sh orm-diff` を使う。
   **突合キーはクラスパスルート（`src/main/resources` 等）からの相対パス**である。
   **basename で比較しない。差分にはフルパスを添える**（件数だけを報告しない）。
   ルート一覧の正本は `gate-snippets.sh` の `orm-diff` で、**どのルートにも当たらないパスが残ったら
   突合不能として FAIL する**（削り残しを黙って差分に数えない）。
2. **「実体のみ」の差分は、マップ先クラスの実在を確認して宣言漏れと死蔵に切り分ける。**
   **クラス名だけで探さない**——同名クラスが別パッケージにあると「実在する」と誤判定する。
   **パッケージを含めたパスで存在を見る**（実測でこれを間違えて死蔵を見逃した）。
   死蔵と判定したら `observed-anomalies.md` に落とす（SB-13）。
   なお**依存 jar 側で提供されるエンティティ**もソースに `.java` が無いので、
   判定は「死蔵の疑い」に留めて確認対象にする（即削除の根拠にしない）。
3. **差が出たら「現行の事実」として扱い、原因を特定する。** 宣言漏れのエンティティは
   永続化されないため、そのエンティティを使う機能は動作しないか別経路で動いている。
   静的読解で断定せず、実装バグ候補として `observed-anomalies.md` に記録する（SB-13）。
4. **エンティティ数の分母は `class=` 属性のユニーク数で取る**（後述 DP-2 の理由）。
5. **DDL（スキーマ生成テンプレート）とも突合する。** ORM 管理外のテーブルを分母に含めるかは
   ADR で決める（暗黙の対象外にしない）。

### 実例
実測（Apache Roller 6.x / `app`）: `*.orm.xml` の実体 **31 ファイル**に対し、
`persistence.xml` の `<mapping-file>` 宣言は **30 件**。差分 1 件は
**`org/apache/roller/planet/pojos/RuntimeConfigProperty.orm.xml`**（フルパスで表記する。
basename の `RuntimeConfigProperty.orm.xml` では次の判定ができない）。
ファイル数だけを分母にすると「31 エンティティを仕様化した」と記録できてしまうが、
そのうち 1 件は JPA が読み込まない。

**さらにこの 1 件は「宣言漏れ」ではなく「死蔵ファイル」だった**（2026-09-23 に再実測して是正）。
マップ先は `org.apache.roller.planet.pojos.RuntimeConfigProperty` だが、
`RuntimeConfigProperty.java` は **`…/org/apache/roller/weblogger/pojos/` にのみ存在**し、
宣言されたパッケージには無い。**クラス名だけで `find` すると `weblogger` 側がヒットして
「クラスは実在する＝宣言漏れ」と誤判定する**（実測で誤判定した）。
つまり正しい対処は「`persistence.xml` に宣言を足す」ではなく「**このファイルを消す**」である。

### チェック方法
```bash
bash 03-audit/gate-snippets.sh orm-diff <src>
# または手動:
# 手動で行う場合も **basename に落とさない**（落とすと同一性が壊れる）。
# ルート一覧は gate-snippets.sh の orm-diff と同じものを使う（値を二重に持たない）。
P=$(find <src> -name persistence.xml -not -path '*/target/*' | head -1)
grep -oE '<mapping-file>[^<]+' "$P" | sed 's#<mapping-file>##' \
  | sed 's#^[[:space:]]*##; s#[[:space:]]*$##' | sort > /tmp/declared.txt
find <src> -name '*.orm.xml' -not -path '*/target/*' \
  | sed -E 's#^.*/(src/main/resources|src/main/java|src/test/resources)/##' | sort > /tmp/actual.txt
grep -c '^/' /tmp/actual.txt   # ★0 でなければルート一覧がこのレイアウトに未対応＝突合不能
comm -23 /tmp/declared.txt /tmp/actual.txt   # 宣言のみ（ファイル欠落）
comm -13 /tmp/declared.txt /tmp/actual.txt   # 実体のみ（宣言漏れ or 死蔵）
```

### アンチパターン
- `find -name '*.orm.xml' | wc -l` をエンティティ数として仕様に書く。
- 宣言漏れを見つけて「たぶん使われていない」と推測で片付ける（実証するか UNKNOWN にする）。
- **差分を basename で報告する**（どのモジュール・どのパッケージのファイルか分からず、死蔵の判定ができない）。
- **マップ先クラスをクラス名だけで `find` して「実在する」と判定する**（同名の別パッケージを拾う）。

## DP-java-struts-ormxml-2: XML 要素を数えるときは要素名の前方一致に注意する

### 目的
XML の要素名は前方一致で別の要素に当たる。`<entity` は `<entity-mappings`（ルート要素）にも
一致するため、素朴な grep は大幅に過大計上する。**桁が違う結果はデータでなくコマンドを疑う**（GP-6（ゲートのコマンド自体を検証する））。

### ルール
1. **要素名の直後に区切り（空白・`>`）を要求する**（`'<entity[[:space:]]'`）。
2. **属性が複数行に分かれる書式では、要素行の grep は成立しない。**
   `<entity metadata-complete="true" name="X"` の次行に `class="..."` が来る書式が実在する。
   **識別に使う属性（`class=`）を直接数えてユニーク化する**のが確実。
3. **`target/` 配下の生成コピーを必ず除外する**（除外しないと件数が倍になる）。
4. **期待値と桁が違ったらコマンドを疑う。** 検算のため 2 通りの数え方で出して一致を確認する。

### 実例
実測（Roller / `app`）: 同じエンティティ集合に対する 3 通りの数え方——
`grep -c '<entity'` = **186**（`<entity-mappings>` を含む過大計上）／
`grep -c '<entity[[:space:]]'` = **93**（属性の折り返し行を重複計上）／
`class=` のユニーク抽出 = **31**（正）。**6 倍の開きがあった。**

### チェック方法
```bash
# 正: class 属性でユニーク化
grep -rhoE 'class="[a-zA-Z0-9_.]*\.pojos\.[A-Za-z0-9_]+"' <src> --include='*.orm.xml' | sort -u | wc -l
```

### アンチパターン
- 要素名の前方一致を確認せずに `grep -c '<要素名'` で数える。
- 1 通りの数え方だけで分母を確定する（検算しない）。

## DP-java-struts-ormxml-3: 画面仕様はアクションクラスとテンプレートの両方から抽出する

### 目的
Struts 2 + Velocity では、入力検証・遷移はアクションクラス側、**条件表示・繰り返し・
表示項目はテンプレート（`*.vm`）側**にある。アクションクラスだけを読むと画面仕様が埋まらない（SB-8）。

### ルール
1. **`<action>` 宣言 → アクションクラス → 結果テンプレート（`<result>`）の 3 点を辿る。**
2. **テンプレート内の条件分岐（`#if`）と繰り返し（`#foreach`）を画面仕様に反映する。**
   「どの条件でどの項目が出るか」は再構築に必須。
3. **`<package extends="...">` の継承を確認する。** 宣言されていない URL が有効になりうるため、
   `<action>` の件数だけでは到達可能な URL 集合と一致しない。
4. **検証定義（`validation.xml` / アノテーション）も画面仕様の一部**として抽出する。

### チェック方法
```bash
find <src> -name 'struts*.xml' -not -path '*/target/*' -exec grep -h '<action \|<result' {} +
grep -rn '#if\|#foreach' <src> --include='*.vm' | wc -l   # テンプレート側の分岐総量
```

### アンチパターン
- アクションクラスのメソッドシグネチャだけで「画面を仕様化した」と記録する。
- テンプレートを「見た目だけ」と判断して読まない（業務ルールが埋まっていることがある）。
