# 仕様章立ての追補（java-struts-ormxml）

ISO/IEC/IEEE 29148 準拠の章立て（GP-8）に対する、このスタック固有の追補。
汎用テンプレート（`specs/*/_template.md`）の節では表現しきれない要素だけを扱う。

- **対象スタック**: Java / Struts 2 / JPA `*.orm.xml` 方式 / Velocity テンプレート

## 追加すべき節（カテゴリ別）

| カテゴリ | 追加する節 | 理由（このスタックで必要になるもの） | 密度の判定基準 |
|---------|----------|--------------------------------|--------------|
| behavior | 画面遷移（アクション → 結果 → テンプレート） | `<action>` の `<result>` 名とテンプレートの対応は XML 側にあり、Java だけでは追えない | アクション 1 つにつき全 `<result>` と遷移先テンプレート |
| behavior | テンプレート内の条件表示・繰り返し | 表示項目と業務ルールが `*.vm` 側にある（DP-java-struts-ormxml-3） | 画面 1 つにつき「どの条件でどの項目が出るか」 |
| api | URL の到達可能性 | `<package extends>` の継承で宣言外の URL が有効になる | パッケージ継承関係と有効 URL の一覧 |
| data | エンティティ ↔ マッピングファイル ↔ テーブルの 3 者対応 | `*.orm.xml` が中間にあり、宣言漏れがあると永続化されない（DP-java-struts-ormxml-1） | エンティティごとに「マッピングファイル・persistence.xml 宣言の有無・テーブル名」 |
| data | ORM 管理外テーブル | DDL にあってエンティティが無いテーブル（ログ・キャッシュ等） | 一覧と、それを操作するコードの `path:line` |
| modules | 検証定義の所在 | 検証は `validation.xml` / アクションのメソッド / テンプレートに分散する | 画面 1 つにつき全検証ルールと発生メッセージ |

## 記述方式の指定

同じ対象を複数の書き方で書くと横断突合ができなくなるため、方式を固定する。

- **画面遷移は mermaid `stateDiagram` で書き、ノード ID を画面 ID（`SCR-NN`）と一致させる**
  （統合画面遷移図のノード数 = SCR 総数の突合に使う。GP-14 ルール6）。
- **アクションの単位は `<action name="...">` 1 つを 1 項目とする**（クラス単位でまとめない。
  同一クラスが複数アクションを持つため）。
- **テンプレートは論理名でなくファイルパスで引用する**（`<result>` の値とパスの対応を明示する）。
- **エンティティは Java クラス FQN で引用する**（`*.orm.xml` の `class=` 属性と突合するため）。

## このスタックで静的読解が効かない箇所（SB-6 の具体化）

- **`persistence.xml` の宣言有無で永続化されるかが決まる**: エンティティ定義があっても
  宣言漏れなら JPA が読み込まない。**実体があることと動作することは別**（実測で 1 件実在）。
- **Struts 2 のインターセプタスタック**: 宣言順・パッケージ継承で認証/検証の適用が決まる。
- **テンプレートのマクロ・include**: `*.vm` が別テンプレートを取り込むため、
  1 ファイルを読んでも画面全体にならない。
- **テーマ・プラグイン機構**: 実行時に読み込まれるテンプレート・フォーマッタがあり、
  静的には配線が確定しない。**どの設定でどれが有効になるか**を列挙する。
