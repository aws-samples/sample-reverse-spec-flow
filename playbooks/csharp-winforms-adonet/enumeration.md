  `find <src> -iname '*.csproj' -not -path '*/obj/*' | head` ／

## 走査の前提（全コマンド共通。破ると件数が黙って狂う）

1. **バイト列で走査する（`LC_ALL=C`）。** .NET の業務アプリは UTF-8（BOM 有無）・ANSI コードページ・UTF-16 が混在する。
   実測: OpenDental は .cs 4,378 本中 BOM 付き 1,547 本・UTF-8 として不正 23 本・CRLF 4,099 本、Estate は 132 本すべて BOM 付き。
   UTF-8 ロケールの awk / grep は不正バイトで**黙って行を落とす**（0 件ではなく「少ない件数」が出るので気づけない）。
   `gate-snippets.sh` は先頭で `LC_ALL=C` を固定している。**手で走査するときも同じにする。**
2. **ファイル名の大小は混在する。** 実測（OpenDental）: `FormHouseCalls.designer.cs` のような小文字の Designer がある。
   `-name '*.Designer.cs'` では落ちる。照合は小文字化してから行う。
3. **パスは解析対象からの相対（`./` 始まり）で出る。** そのまま `path:line` の引用に使える。

## 走査の落とし穴（このスタック固有。すべて実測で確認済み）

番号は `gate-snippets.sh` のコメントと対応する（「落とし穴 N」で検索できる）。
実測値は特記の無いかぎり C# の OpenDental / Estate。VB.NET の OSS でだけ観測したものは「VB.NET で実測」と書く（機構は C# でも同じ）。

1. **文字コードの混在（`LC_ALL=C`）。** 前提 1 を参照。UTF-8 ロケールでは不正バイトの行が黙って落ちる。
2. **識別子は非 ASCII を許す。** 実測（Estate）: `public partial class 楼房ADD : Form` のような中国語名の画面があり、
   `[A-Za-z_][A-Za-z0-9_]*` で名前を切ると画面が 2 件消えた。名前は「区切り文字以外の連続」で切る。日本語名でも同じ。
3. **大文字小文字の混在。** 前提 2 を参照（小文字の `.designer.cs`）。
4. **コメントと文字列を区別する。** 素の grep は、コメントアウトされたクラス宣言・旧 SQL、文字列中の `//`（URL）、
   逐語的文字列 `@"..."` の複数行 SQL を区別できない。`gate-snippets.sh` は字句解析（行コメント・ブロックコメント・
   通常文字列のエスケープ・逐語的文字列の `""`・文字リテラル）をしてから数える。`#if false` / `#if 0` 〜 `#endif` の中も数えない。
   型宣言は `class X\n  : Form` のほか `class X :\n  Form`（行末の `:`）の形も読む（反証レビューで「落ちる」ことを合成入力で実証した）。
5. **外部部品の基底フォーム。** 継承の根を `Form` に限ると、`XtraForm`（DevExpress）・`RadForm`（Telerik）等を継承した画面が全部落ちる。
   VB.NET で実測（School）: 30 画面すべてが `XtraForm` 継承で、`Form` からの閉包は 0 件。
   `gate-snippets.sh` は「ソースに宣言が無く、**宣言の綴りが `Form` で終わる**基底」を根に加え、`I` ＋大文字で始まるインタフェース名は除く
   （小文字の `form` で判定すると `ICryptoTransform` / `Transform` を実装・継承したクラスが画面になる。反証レビューで実証）。
   **加えた根は `ep-diff` が列挙するので人が確認する**。
6. **ファイルがあることとビルドされることは別。** 旧形式（`ToolsVersion`）の `.csproj` は `<Compile Include>` の列挙がビルド対象の全数で、
   列挙に無いファイルはディスクにあってもビルドされない。SDK 形式（`<Project Sdk=`）は逆に既定で全ファイルを含み、`Remove` で外す。
   実測: 旧形式のプロジェクトに無い `Form` 派生クラスが OpenDental 21 件・Estate 7 件あり、`ep-diff` が「ビルド対象外」と判定した。
   **画面の単位はクラス**（`X.cs` と `X.Designer.cs`、partial の分割ファイルは 1 画面）。実測 OpenDental: ファイル単位では 967、
   クラス単位では 964（`FormOpenDental` が 3 ファイル、`FormPerio` が 2 ファイルに分かれていた）。`SubType=Form` も分割ファイル・
   Designer 側に付くので、経路B もファイルが宣言するクラスに寄せて数える（VB.NET で実測: Designer 側の SubType）。
7. **起動点はプロジェクトの `OutputType` で数える。** `static void Main` は 1 実行ファイルに 1 つだが、
   ツール・テスト・試作の `Main` もリポジトリに混ざる。実行ファイルのプロジェクトを起点にし、その中の `Main` を起動対象として読む。
   実測: OpenDental（部分取得）の実行ファイル 1、Estate 2（うち 1 件は `.sln` に載らない試作。落とし穴 12）。
8. **イベント配線は画面ごとに数える。** 画面を跨いで `sort -u` すると、`Form_Load` のような同名ハンドラが潰れる。
   `list-handlers` は全ファイルの配線を出し、4 列目で画面（`screen`）とそれ以外（ユーザーコントロール・業務クラス等の `other`）を分ける。
   **画面仕様の操作の分母は `screen` の行だけ**（実測 OpenDental: 全 8,961 のうち画面の配線は 7,436）。
   実測（画面の配線）: (画面, イベント元, ハンドラ) の対は OpenDental 7,436・Estate 193。**ハンドラ名だけで全体を `sort -u` すると 4,439・105**（4 割減）。
   **配線でない `+=` と区別する**（`total += price;` / `this.Location += new Size(5, 5)` / `text += (a ? b : c)` を拾わない）——
   ハンドラは `new XxxHandler(...)`・ラムダ（`(s, e) =>` / `x =>` / `delegate`）・同じファイル群で宣言されたメソッド名に限る
   （括弧で始まる式をラムダと見なした版は、OpenDental でラムダの配線を 90 件と数えていた。形まで確かめると 58 件——差の大半は文字列・数値の `+=` だった。反証レビューで実証）。
   1 行に `+=` が複数あれば全部読む。`this.` を付けない `Load += ...` の形は拾わない（Designer は常に `this.` 付き）。
9. **英文メッセージを SQL と誤認しない。** 「`from` / `select` を含む文字列」を SQL と見なすと、
   `"Select the item from the list"` の `list` が表名に化ける。SQL 句の語で**始まる**リテラルだけを SQL と見なし、
   先頭語が「先頭だけ大文字」（`Select` / `From`）なら英文として除く。小文字で始まる英文（`"select an item from the list"`）は
   英文に特有の語（the / your / please / you）を含むことで除く（`an` は `FROM t4 an` のような別名ごとリテラルを消すので入れない。除外語を含まない英文——例: `select an item from list`——は通るので、参照側にしか無い表は差分欄で処分する）。**SQL の文字列値 `'...'` は先に消す**（実測 OpenDental: `'...From your friends'` の `your`）。
   実測（OpenDental）: 「語を含む」判定 930 表 → この判定 544 表。参照側にしか無い 213 表の大半は本体以外の DB の表・一時表・
   システム表・クラス名と物理名の違い（落とし穴 15 の下の注）で、**英単語らしき残り（`this` / `previous` / `width` 等）が十数件ある**——差分欄で個別に処分する。
   補間式（`$"... FROM {GetTableName()}"`）・URL も表名から除く。
   **先頭語の判定はコード中のリテラルにだけ掛ける**（`.sql` の行は `FROM` 句が継続行に来るので掛けない。`--` コメントは除く）。
10. **UTF-16 の `.sql` / `.xml`。** SSMS の「スクリプト生成」は既定で UTF-16 LE を出し、VS が保存した XML も UTF-16 のことがある。
    素の grep は 1 件も拾わない。VB.NET で実測（School）: `.sql` の `CREATE TABLE` 13 件が 0 件に見えた。
    `gate-snippets.sh` は BOM を見て NUL を落としてから読む（**非 ASCII の表名は崩れる**ので一覧で目視する）。
    **ソース本体（`.cs`）が UTF-16 の場合は字句解析が読めない（未対応）**。前提 1 の文字コード確認のときに
    先頭 2 バイトが `ff fe` / `fe ff` のファイル（`head -c 2 <file> | od -An -tx1` で確かめる）を探し、見つけたら UTF-8 に変換した写しを解析対象にする。
    BOM の無いレガシーコード（GBK・Shift_JIS 等）の `.sql` も混ざる（実測 Estate: ストアド定義の `.sql` 2 本が BOM の無い中国語の ANSI コードページ）——バイト列で読めば ASCII の識別子は拾える。
11. **SQL がコードに無いことがある（外部 SQL 置き場）。** 名前付き SQL を XML や独自拡張子のファイルに置き、コードは名前で引く設計がある。
    VB.NET で実測（Apskaita5）: コード中のリテラルから見える表は 3、独自拡張子の SQL 置き場を加えると 76。
    **`sql-stores` で SQL を含むコード以外のファイルを拡張子別に探し**、見つけた拡張子を `00-ingestion/gate-config.env` に `SQL_STORE_GLOBS='*.sqld'` の形で書く（`gate-snippets.sh` が読む。Phase 4 の再実行でも同じ値が使われる）。
12. **`.sln` の宣言と実在のプロジェクトはずれる。** `.sln` にはソリューションフォルダ・セットアップ（`.vdproj`）・Web サイトも載り、
    参照切れ（ファイルが無い）も残る。実測（Estate）: 実在 2 件のうち 1 件はどの `.sln` にも載らない試作。
    `mod-diff` は拡張子で絞り、両方向の差を出す。**断面を部分取得した場合**は `.sln` の宣言の大半が「ファイルが無い」に出る
    （実測 OpenDental の部分取得: 宣言 32 件・実在 4 件。宣言のみ 29 件のうち 17 件は部分取得の外、
    **12 件は公開リポジトリのどこにも無い**＝参照切れ）——**差を「参照切れ」と「断面外」に分けて書く**。
13. **システムカタログ・FK の動作句は表ではない。** SSMS の生成スクリプトは `sys.objects` / `sys.foreign_keys` を参照し、
    `ON DELETE CASCADE` の `CASCADE` は `delete` の後に来る。VB.NET で実測（School）: 除外前は 16 表、除外後 13 表（定義側と一致）。
14. **ストアドは DB ヘルパー越しに呼ばれる。** `DBHelper.Exec("proc", ...)` のように手続き名を引数で渡し、
    `CommandType.StoredProcedure` を設定するファイルには名前のリテラルが無い。実測（Estate）: ヘルパーを辿らないと呼び出し 0 件、
    辿ると 31 箇所（手続きの名前で一意に 27）。`list-sproc` は「`StoredProcedure` を使うファイルが宣言する、先頭引数が `string` のメソッド」を
    ヘルパーとみなして呼び出し側を辿る（ヘルパーのファイルにある他の `string` 引数のメソッドも巻き込むので、`via` 列で確かめる）。
    `EXEC <名前>` のリテラルは `StoredProcedure` の指定が無くても拾う。
    定義 51 のうち 24 は呼び出し側に現れない（死蔵か、動的に名前を組み立てて呼ぶ）——**呼ばれない定義を黙って仕様から落とさない**。
15. **表名の綴りは大小が揺れる。仕様は `idents-table` の綴りで書く。** SQL は表名の大小を区別しないので、同じ表が複数の綴りで書かれる
    （実測 OpenDental: 2 通り以上の綴りで現れる表が 18）。`gates.sh` の `G-IDENT` は**大小を区別して** `specs/` 本文と突合するため、
    `idents-table` は表ごとに最も多く現れた綴りを 1 つ出す。突合の分母（`list-bnd` / `bnd-diff`）は小文字に揃えて数える。
    画面名（`idents-screen`）は宣言どおりの綴りで出る。
16. **表名の切り出し: 別名・カンマ結合・角括弧・一時表。** `DELETE a FROM t a` の `a` は別名（表は `FROM` の後）。
    `FROM t1 a, t2 b` は 2 つ目以降の表も拾う（実測 Estate: `FROM [dbo].[x],[dbo].[ZUIXINXIAOXI]` の 2 つ目を取りこぼしていた。11 → 12 表）。
    `[Order Details]` / `[Order]` のように角括弧で囲んだ名前は、空白を含んでも予約語でもそのまま表名にする。
    `CREATE TABLE #work` の一時表は定義側の表にしない。いずれも反証レビューで合成入力により実証した。

### 逆引き索引の分母（`SOURCE_EXCLUDE`）

`gate-config.env` の `SOURCE_EXCLUDE`（POSIX ERE）は、逆引き索引（`GP-4` ルール7〜8）が
**引用を実ファイルへ解決するときの分母**から除くパスを決める。**Phase 0 で設定する。**

```sh
# ビルド出力・NuGet パッケージ・VS のキャッシュを除く（この Playbook の列挙と同じ除外にそろえる）
SOURCE_EXCLUDE='(^|/)(bin|obj|packages|[.]vs)/'
```

**入れないとどうなるか**: `obj/` には `*.Designer.cs` や `.g.cs` の生成コピーが入り、
basename の引用が「候補複数」で解決できなくなる。索引は 10% を超えると原因と対処を本文に書く。

**値は必ず引用符で囲む**（囲まないと `gate-config.env` が bash の構文エラーになり `gates.sh` が中断する）。
