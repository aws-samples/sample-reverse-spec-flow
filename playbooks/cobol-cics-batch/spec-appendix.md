# 仕様章立ての追補（cobol-cics-batch）

ISO/IEC/IEEE 29148 準拠の章立て（GP-8）に対する、このスタック固有の追補。
汎用テンプレート（`specs/*/_template.md`）の節では表現しきれない要素だけを扱う。

- **対象スタック**: COBOL / CICS（BMS）/ JCL / DB2 / VSAM（IMS・MQ の併用を含む）

## 追加すべき節（カテゴリ別）

| カテゴリ | 追加する節 | 理由（このスタックで必要になるもの） | 密度の判定基準 |
|---------|----------|--------------------------------|--------------|
| behavior | オンラインの入口と画面遷移 | 疑似会話型では 1 画面が複数の起動に分かれ、遷移先は変数経由で決まる（DP-cobol-cics-batch-2） | トランザクション 1 つにつき初期プログラム・マップ・PF キーごとの遷移先 |
| behavior | 画面項目定義 | 位置・長さ・属性・初期値は BMS の `DFHMDF` にしか無い | マップ 1 つにつき `DFHMDF` の全数 |
| behavior | バッチのジョブフロー | 処理順序・条件実行・ユーティリティは JCL が決める（DP-cobol-cics-batch-3） | ジョブ 1 つにつき全ステップの PGM・DD・実行条件 |
| data | レコード定義と物理の定義の対応 | 項目の型と桁はコピー句、キーと編成は DDL・VSAM・DD にある（DP-cobol-cics-batch-4） | ファイル・表 1 つにつき論理名・物理名・コピー句・キー |
| data | 画面・ジョブ × 表・ファイルの CRUD マトリクス | 読み書きは EXEC SQL / EXEC CICS / JCL の DD に分散する | 入口 1 つにつき参照・更新する全データと操作 |
| modules | プログラム間の呼び出し | `CALL`・`LINK`・`XCTL` は変数経由のことが多い | プログラム 1 つにつき呼び出し先（変数経由は候補の全値） |
| modules | 共通部品（コピー句・共通サブプログラム） | 業務ルールの定数・チェック処理がコピー句に置かれる | コピー句 1 つにつき使うプログラムと役割 |
| api | 外部との境界（MQ・IMS・ファイル転送・帳票） | 他システムとの受け渡しはキュー・データセットで行う | 境界 1 つにつき相手・形式・タイミング |

## 記述方式の指定

同じ対象を複数の書き方で書くと横断突合ができなくなるため、方式を固定する。

- **名前は大文字の物理名で書く**（プログラム名・トランザクション ID・マップ名・表名・DD 名）。`idents-*` の出力と一致させる（G-IDENT は大小を区別する）。
  業務の言葉の名前を添えるのはよいが、物理名を省かない。
- **引用はソースの `path:line` で書く**（`gate-snippets.sh` の出力のパスと行番号）。行番号は 1〜6 桁の連番ではなくファイルの行番号。
- **遷移は「トランザクション ID / プログラム → 遷移先」を 1 行ずつ書く**（`CAUP: COACTUPC → XCTL COMEN01C（PF3）`）。
- **画面遷移図は mermaid `stateDiagram` で書き、ノード ID をトランザクション ID と一致させる**（統合画面遷移図のノード数 = オンラインの入口数の突合。GP-14 ルール6）。

## このスタックで静的読解が効かない箇所（SB-6 の具体化）

- **変数経由の名前**: `XCTL PROGRAM(項目)` / `FILE(項目)` の値は MOVE・VALUE で決まり、表（OCCURS）の要素経由は静的に決まらない。
- **COMMAREA の受け渡し**: 画面の状態は COMMAREA で次の起動に渡る。どの項目がどの遷移で設定されるかを書く。
- **資源定義の属性**: トランザクションの優先度・ファイルの読み書き属性（`ADD` / `UPDATE` / `BROWSE`）は資源定義にあり、コードからは分からない。
- **JCL の記号パラメータ・プロシージャ**: `&HLQ` などの値は実行時の指定・プロシージャの既定値で決まる。テンプレート（`.j2` 等）なら配備時に決まる。
- **スケジューラとオペレーション**: ジョブの起動順序・起動条件・再実行の手順は JCL に無い（断面外として明示する）。
- **コンパイル・リンクのオプション**: `CBL` / `PROCESS` 文・リンクの指定で動作が変わる（例: 動的 CALL か静的 CALL か）。
