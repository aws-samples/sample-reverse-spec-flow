汎用手順書（pipeline-procedure）は「この表に従う」と抽象で書き、具体はここに置く。
下記のコマンドと件数はすべて OSS 3 件で実測検証済み（2026-10-23）:
  AWS CardDemo（クレジットカード管理。CICS ＋ VSAM ＋ JCL ＋ DB2/IMS/MQ の拡張。COBOL 44 本・JCL 55 本）
  IBM Bank-of-Z（銀行業務。CICS ＋ DB2 ＋ IMS。資源定義が YAML、JCL が Jinja2 テンプレート。COBOL 43 本）
  IBM CICS GenApp（損害保険の汎用アプリ。CICS ＋ DB2 ＋ VSAM。資源定義が JCL の DFHCSDUP 入力。COBOL 31 本）
走査コマンドの実体は `03-audit/gate-snippets.sh`（この表の「全走査コマンド」はそのサブコマンド名）。

- **対象スタック**: IBM メインフレームの COBOL アプリ。オンラインは CICS（BMS 画面・EXEC CICS）、バッチは JCL、
  データは DB2（EXEC SQL）・VSAM（CICS のファイル・IDCAMS）。IMS・MQ を併用するものも含む。
  PL/I・アセンブラが混在する場合、その部分はこの Playbook の走査の対象外（件数に入らない。README を参照）。
- **適用判定**: 次の 2 つがどちらも 1 件以上。
  `find <src> -type f \( -iname '*.cbl' -o -iname '*.cob' -o -iname '*.cobol' \) | head` ／
  `grep -rliE 'PROGRAM-ID' <src> --include='*.cbl' --include='*.cob' --include='*.cobol' | head`
  （メインフレームから落としたメンバーに拡張子が無い場合は、拡張子を付けた写しを解析対象にする。README を参照）

## 走査の前提（全コマンド共通。破ると件数が黙って狂う）

1. **固定形式の桁を守る。** 1〜6 桁は連番、7 桁目が標識（`*` `/` は注釈、`D` はデバッグ行、`-` は継続）、8〜72 桁が本文、
   73〜80 桁は識別領域（コンパイラは読まない）。`gate-snippets.sh` は字句解析してから数える。**手で grep するときも 73 桁目以降を切る。**
2. **バイト列で走査する（`LC_ALL=C`）。** `gate-snippets.sh` は先頭で固定している。
3. **大文字小文字を区別しない。** COBOL・JCL・CICS の語は大小を区別しない（実測 GenApp: 小文字の本文が 2,667 行、`Program(` のような混在）。
   `gate-snippets.sh` は大文字に揃えてから照合し、名前も大文字で出す。
4. **データファイル（EBCDIC のバイナリ）は走査しない。** 実測 CardDemo: `data/EBCDIC/` 以下はバイナリ。拡張子で対象を絞っている。
5. **パスは解析対象からの相対（`./` 始まり）で出る。** そのまま `path:line` の引用に使える。

## 走査の落とし穴（このスタック固有。すべて実測で確認済み）

番号は `gate-snippets.sh` のコメントと対応する（「落とし穴 N」で検索できる）。

1. **73〜80 桁の連番と、はみ出たコード。** 実測 CardDemo: 73〜80 桁に連番がある行が 4,340。切らないと、72 桁目で終わる名前の後ろに
   連番が付く（`PGMB00110000`）。逆に**72 桁を越えて書かれたコードはコンパイラが読まない**（実測 Bank-of-Z: IMS のロードプログラム 5 本で、
   `UNSTRING ... DELIMITED BY` の区切り文字の一部が 73 桁目以降にあった）。`overflow` が報告するので `observed-anomalies` に記録する。
   73〜80 桁は識別領域で、連番以外の文字（変更の目印）も正当に置かれる（実測 CardDemo: 縦に並べた 1 文字の目印が 14 行）——
   `overflow` は語が境界をまたぐ行と、73 桁目以降に引用符・括弧・ピリオド等がある行だけを報告する。
2. **自由形式のソース。** `>>SOURCE FORMAT FREE` のソースは桁で切らず、`*>` 以降を注釈とする（実測 Bank-of-Z: 行の途中の `*>` 注釈が 12）。
3. **継続行（7 桁目が `-`）。** 英数字リテラルは次の行の最初の引用符の後から続く（実測 CardDemo: 11 行）。継続を読まないと
   `VALUE` の値が途中で切れ、項目名経由の名前が解決できない。
4. **タブ。** 8 桁ごとのタブ位置に展開してから桁で切る（実測: タブを含むソースが CardDemo 3・Bank-of-Z 2）。
   **タブの幅はソースから分からない**——実測 CardDemo: 登録集 `CUSTREC.cpy` の 17 行は、タブ幅 8 で展開すると `PIC X(25).` の末尾が
   73 桁目以降に出る（他の行の桁揃えから見て、元はもっと狭いタブ幅で書かれている）。`overflow` はこれを「タブを含む行」と付記して報告する。
   メインフレームへの転送でタブがどう扱われるかを確かめるまで、はみ出しとも正常とも決めない（`observed-anomalies` に記録する）。
5. **COBOL の語は `-` を含む。** 単語境界を「英数字以外」で取ると `WS-CALL` の `CALL` を CALL 文と読む。
   **文字列の中の `CALL`**（`DISPLAY 'CALL FAILED'`）も文ではない（実測 CardDemo: `FAILED` / `FAIL` / `TO` が呼び出し先に混入した）。
6. **CICS の資源定義の置き場所は対象ごとに違う。** 実測: CardDemo は CSD の抜き出し（`.csd`）、GenApp は JCL の DFHCSDUP の入力データ、
   Bank-of-Z は YAML（`- transaction:` の下に `name:` / `program:`。CICS TS の構成ファイル）。1 形式だけを見ると他の 2 件で定義が 0 件に見える。
   DFHCSDUP の入力と CSD の抜き出しでは 1 桁目が `*` の行が注釈で、注釈にした古い `DEFINE` を数えない。
7. **注釈とデバッグ行。** 7 桁目が `*` / `/` の行は注釈、`D` の行はデバッグ行（`WITH DEBUGGING MODE` のときだけ動く）。
   実測 Bank-of-Z: デバッグ行が 54。数えない（仕様に書くなら「デバッグ時のみ」と明記する）。
8. **大文字小文字の混在。** 前提 3 を参照。DDL の表名は小文字でもコードは大文字のことがある（実測 GenApp: DDL は `customer`、コードは `CUSTOMER`）。
9. **名前が項目名（変数）経由で書かれる。** `FILE(LIT-ACCTFILENAME)` の値は `VALUE 'ACCTDAT'`、`XCTL PROGRAM(CDEMO-TO-PROGRAM)` の値は
   `MOVE 'COACTVWC' TO CDEMO-TO-PROGRAM` にある。登録集（COPY）の中の VALUE も引く。VALUE の書き方は揺れる（`PIC X(8)` / `PIC XXXXXXXX` / `VALUE IS` / PIC より前の VALUE）。実測 CardDemo: CICS のファイル 8 件すべてが VALUE 経由、
   画面遷移の `XCTL` の大半が MOVE 経由。`gate-snippets.sh` は `MOVE 'リテラル' TO 項目` と、項目から項目への `MOVE` を 1 段だけ辿る
   （実測 CardDemo: 辿った後の未解決は 3）。
   **表（OCCURS）の要素経由**（`PROGRAM(CDEMO-MENU-OPT-PGMNAME(WS-OPTION))`）は静的に決まらないので「未解決」として残る——
   メニューの表の VALUE を読んで手で補う（実測 CardDemo: 未解決の名前 3 のうち 2。呼び出し箇所で数えると 4 のうち 3）。残る 1 は**登録集の中の CALL で、項目の VALUE を
   取り込む側のプログラムが持つ**もの——取り込む側を読んで手で補う。
10. **参照のみのプログラム名は「システム提供」と「断面外」に分ける。** `IDCAMS` / `IKJEFT01` / `DFHCSDUP` / `CEE*` / `DSN*` 等は製品が提供する
    （実測 Bank-of-Z: 参照のみ 296 のうち 287 がシステム・製品提供の疑い）。それ以外は**ソースが断面に無い**——実測 CardDemo:
    CSD に定義があってソースが無いプログラムが 6（管理・テスト用の `COADM00C` / `COTSTP1C` 等）、マップセットが 15。
    `mod-diff` は接頭辞で「システム・製品提供の疑い」と付記するだけで、件数から落とさない。
11. **コードから名指しされないトランザクション。** 開始トランザクション（端末から入力）・製品提供（ソケットの `EZAC`、デバッガの `DTCN` 等）・
    テスト用はコードの `TRANSID` に現れない。実測: 定義のみ CardDemo 9・Bank-of-Z 26・GenApp 19（GenApp は 15 件が CICS のミラー `DFHMIRS`）。
12. **BMS のファイル名・マップセット名・マップ名は一致しないことがある。** 実測 Bank-of-Z: `BNK1B2M.bms` のマップセット名は `BNK1TFM`
    （別ファイルと重複。複製の残り）で、資源定義の `BNK1B2M` に対応するマップセットが無い。また `BNK1CCM.bms` のマップは `BNK1CC` だが、
    コードは `SEND MAP('BNK1CCM')` を送る（マップセット名をマップ名に書いている）。`screen-diff` が両方を出すので `observed-anomalies` に記録する。
13. **JCL の入力データの SQL も表の参照。** DB2 のアンロード・バッチ SQL（`IKJEFT01` で `DSNTIAUL` / `DSNTEP2` を流す等）は SQL を JCL に書く。
    実測 CardDemo: `TRANSACTION_TYPE_CATEGORY` は JCL からしか参照されない。ただし**入力データを SQL として読むのは DB2 のステップだけ**——
    DFHCSDUP・IDCAMS・IMS のコマンド・SORT の制御文は SQL ではない（実測: IMS の `UPDATE DB` と CSD 定義の注釈が表に化けた）。
14. **SQL の中の表でないもの。** `FOR UPDATE OF <列>`・`CURRENT OF <カーソル>`・`FETCH FROM <カーソル>`・ホスト変数（`:WS-X`）・
    システム表（`SYSIBM.SYSDUMMY1`）・`-` を含む名前（COBOL の項目名）。実測で GenApp の `OF`、Bank-of-Z の `ACC-CURSOR` が混入した。
    **関数の引数の `FROM`**（`EXTRACT(YEAR FROM ...)`・`TRIM(LEADING '0' FROM 列)`・`SUBSTRING(... FROM ...)`）も表の前置詞ではない——
    `gate-snippets.sh` は `SELECT` を含まない括弧の中身を消してから探す（副問い合わせの括弧は残す）。
    `FROM T1 X, T2 Y` / `FROM T1 AS X, T2 AS Y` のカンマ結合は 2 つ目以降も拾い、`LOCK TABLE` も表の参照に数える。
15. **テンプレートの記号。** JCL・DDL が配備用のテンプレートになっていることがある（実測 Bank-of-Z: JCL が Jinja2 の `.j2`、DDL の
    スキーマが `{{ }}`。GenApp: DDL のスキーマが `<DB2DBID>`）。名前の部分だけを取り、テンプレートの記号は名前にしない。
16. **YAML の `#` は空白の後だけが注釈。** トランザクション ID に `#` を含むものがある（実測 Bank-of-Z: `CDT#`）。`#` で切ると別の ID になる。
17. **見出し部の注記項目は自由な文章。** `AUTHOR.` / `INSTALLATION.` / `DATE-WRITTEN.` / `DATE-COMPILED.` / `SECURITY.` / `REMARKS.` の後は
    COBOL の語でもリテラルでもない。人名のアポストロフィ（`O'NEIL`）をリテラルの開始と読むと、**以降のファイル全体で
    リテラルの内外が反転し**、CALL・EXEC の名前が黙って消える。`gate-snippets.sh` は次の見出し部の段落（`PROGRAM-ID` 等）・
    部の見出し（`... DIVISION`）までを注記として読み飛ばす。**注記と読むのは見出し部の中だけ**——手続き部の段落名 `SECURITY.` を
    注記の始まりと読むと以降の文が消え、注記の文章の途中の `DATA ...` で始まる行を終わりと読むとそこから反転する。
18. **ジョブ名は一意ではない。** JCL のメンバーごとに `JOB` 文が 1 つあるが、別メンバーが同じジョブ名を使い回す
    （実測: Bank-of-Z はメンバー 15 で名前 12、GenApp はメンバー 29 で名前 17。CardDemo は 55 で一致）。`list-ep` の `job` 行は
    **メンバー単位**で出す（パス付き）。ジョブ名に配備用のテンプレートの記号が残るものもある（`<CMASAPPL>`・`{{TASK_NAME}}`）。
    また OSS の JCL の多くは**導入・配備用のジョブ**（資源定義・DB2 の作成・コンパイル）で業務のバッチではない——
    業務のバッチと導入用を分け、導入用を分母から外すなら ADR で処分する。
19. **DD 文は 1 行とは限らない。** `DSN=` が継続行にある形（`//IN1 DD DISP=SHR,` の次行に `//    DSN=...`）と、名前欄が空の
    **連結 DD**（`//        DD DSN=...`。直前の DD 名に連結される）がある。`DD` と `DSN=` が同じ行にある形だけを数えると
    **データセットの約半分を取りこぼす**（実測: CardDemo 165 → 344、Bank-of-Z 119 → 201、GenApp 74 → 110）。`list-dd` は DD 文の
    続きの行（名前欄が空で、最初の語が文の種類でない行）まで見て、連結 DD は直前の DD 名で出す。

### 逆引き索引の分母（`SOURCE_EXCLUDE`）

`gate-config.env` の `SOURCE_EXCLUDE`（POSIX ERE）は、逆引き索引（`GP-4` ルール7〜8）が
**引用を実ファイルへ解決するときの分母**から除くパスを決める。**Phase 0 で設定する。**

```sh
# データファイル（EBCDIC のバイナリ・テスト用の入力データ）とコンパイル出力を除く
SOURCE_EXCLUDE='(^|/)(data|listing|lst|obj)/'
```

**入れないとどうなるか**: データファイルやコンパイルリストに同名のメンバーが入り、basename の引用が「候補複数」で解決できなくなる。
索引は 10% を超えると原因と対処を本文に書く。

**値は必ず引用符で囲む**（囲まないと `gate-config.env` が bash の構文エラーになり `gates.sh` が中断する）。
