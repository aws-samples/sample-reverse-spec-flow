# entry.md — Kiro CLI の規範の読ませ方とツール名対応表（GP-107）

根拠はすべて `MEASURED.md`（kiro-cli 2.33.0 / 2026-10-21）。**Kiro IDE の実測を流用しない**（別製品。GP-107 ルール2）。
kiro-cli には 2 つのエンジン（既定の V2 と `--v3`）があり、**挙動がエンジンで違う**。ここではエンジンを明記する。

## 1. 規範の読ませ方

| 文書 | 扱い | 根拠 |
|---|---|---|
| ルート `AGENTS.md` | 起動ディレクトリ直下のものを**起動時に注入する**（V3） | 項目 1 |
| `.kiro/steering/` | 起動ディレクトリのものを**起動時に注入する**（V3）。**生成先には作らない** | 項目 1 |
| `specs/AGENTS.md` ／ `spec-extraction/AGENTS.md` | V2 は読まない。**V3 はそのディレクトリにアクセスすると注入する**（読み取りが deny で拒否されても注入される） | 項目 1 |

**帰結**: ルート入口に対象固有の値（解析対象パス・purpose・スコープ）を書かない。
V3 ではアクセスしただけで入れ子の規範が入るので、**検証官を仕様リポジトリの中で起動すると、
読ませていない規範を持った状態で検証を始める**（§5 で別セッションにする理由）。

## 2. ツール名対応表

| 役割（抽象） | Kiro CLI でのツール名 |
|---|---|
| サブエージェントを起動する | V2: `subagent`／V3: 「Sub-agent」（`general-task-execution`）と表示される。**隔離した検証官には使わない（§5）** |
| 隔離した検証官を起動する | `bash spec-extraction/03-audit/kiro-verify.sh <指示文ファイル>`（§5） |
| ファイルを読む | `read_file`（公式ドキュメントの ID。ACP の `kind` は `read`）。**検証官では信頼しない**——ワークスペース内は既定の許可で読め、ID を信頼すると外も読めてしまう（追補 V3-1） |
| ワークスペースを検索する | **専用ツールは無い**（V3。`grep` / `glob` / `grep_search` / `file_search` のどれも存在せず、検索の要求はシェルに落ちる。追補 V3-1・3/3）。検索はシェル＝対話では承認、非対話では拒否。禁止事項 4 |
| シェルを実行する | 非対話モードで**シェルだけを信頼させる `--trust-tools` の名前は見つかっていない**（`shell`・`execute_bash`・`bash`・`execute_cmd` はいずれも確認待ち＝拒否） |

## 3. このホスト固有の禁止事項

| # | 禁止・制約 | 理由 |
|---|---|---|
| 1 | **生成先に `.kiro/steering/` を作らない。生成物（`02-analysis/` ／ `specs/` ／ `code-graph.md`）を steering やエージェントの `resources` に入れない** | V3 は起動時に steering を注入する。検証官にも入るので `GP-22` の隔離が**静かに**破れる |
| 2 | **隔離した検証官を、仕様リポジトリの中のサブエージェントや別セッションで代用しない** | V3 はアクセスしたディレクトリの `AGENTS.md` を拒否されても注入し、カスタムエージェントの `permissions` の deny はワークスペースの外に効かない。ワークスペースの中なので検証官が分析物を読みに行くことも塞がらない |
| 3 | **検証官のセッションに `--trust-all-tools` を付けない** | ワークスペースの外への読み取りまで承認してしまう（境界が隔離にならない） |
| 4 | **ホストの検索結果を解析対象の走査に使わない。0 件を「無い」と読まない** | V3 に専用の検索ツールは無く、シェルに落ちた検索は非対話では拒否される（0 件でなく拒否になるが、対話で承認した場合もワークスペース外の走査は成果物に残らない。`GP-107` ルール6）。解析対象の走査はシェルで行い、コマンドと件数を成果物に残す |
| 5 | **ルート `AGENTS.md` に解析対象パス・`purpose`・スコープを書かない** | 起動時に注入される。隔離の要件である |

## 4. 既知の制約

| 項目 | 実測 |
|---|---|
| 解析対象（ワークスペースの外）へのアクセス | 確認待ちになる。`--no-interactive` では拒否、`--trust-all-tools` では承認（V3） |
| 無人実行 | **未測定。** 非対話モードでシェルだけを信頼させる方法が見つかっていない |
| skill | V3 は `.kiro/skills/` だけを読む。V3 の非対話モードでは skill の読み込み自体が確認待ち＝拒否になる（対話では承認して読む） |
| 生成パイプライン全体 | **回していない**（`SUPPORT_LEVEL=placed-unverified`）。ゲートの実時間・出力上限・並列の上限は未測定 |

## 5. 検証官の隔離（GP-16 ルール2）

skill（`density-verify` §2・`spec-adversarial-audit` 手順 3）は「読み取りを解析対象ソースの配下に
機械で制限する起動手段」とだけ書いている。この節は、その手段のこのホストでの実体と、隔離の確かめ方を示す。
根拠は `MEASURED.md` 項目 4・5。

**作業ディレクトリは仕様リポジトリのルートにする**（下のパスはルートからの相対）。
**他ホストの手段（`.claude/agents/spec-verifier.md` など）が残っていても使わない**（ホストを切り替えた後の残置物）。

**起動**: 指示テンプレートを埋めてファイルに書き（`spec-extraction/03-audit/verify-log/` の下などリポジトリ内でよい）、
**1 ブロックずつ** `bash spec-extraction/03-audit/kiro-verify.sh <指示文ファイル>` を実行する。標準出力が検証結果である。
スクリプトは**解析対象ソースをワークスペースにした V3 の別セッション**（`--no-interactive --trust-tools=`＝**何も信頼しない**）を起動する。ワークスペース内の read は Kiro の既定の許可（`fs_read` は `./**`）で通り、
外は確認待ち＝拒否される。**`--trust-tools` にツール ID（`read_file`）を書かない**（境界を問わず承認され、外も読める。追補 V3-1 #9）。
仕様リポジトリはワークスペースの外なので、その steering・`AGENTS.md` は読み込まれず、外への読み取りは拒否される。

**この検証官は渡されたパスの read しかできない**（追補 V3-1）。V3 に検索ツールは無く、シェルは既定で確認待ちなので、
検証官が検索を試みれば拒否される（スクリプトはその拒否を数えて rc=6 にする。初版は拒否行を出力から除いて rc=0 で返していた）。
スクリプトは指示文の前に「使えるツールは Read だけ・渡された**ファイル**だけを読む」を前置する（ディレクトリは列挙できないので、
【原典パス】には**ファイル**を列挙する）。帰結:

| 主張の型 | この検証官で検証できるか | 条件 |
|---|---|---|
| 引用の実在・内容・固有名・live か・強度（指示テンプレートの検査項目 1〜5）、渡されたファイルの中の missing | **できる** | 引用されたファイルを【原典パス】に渡す |
| 唯一型・全称型・不在型（「唯一」「すべて」「他に無い」「0 件」） | **分母を機械で決めたときだけできる** | 【原典パス】に**母集団の走査コマンド**（`母集団:` 行。`G-POPULATION`）**の出力を全部**列挙する。スクリプトは Read 数が件数未満なら rc=7 で捨てる。候補を生成側の判断で選んで渡した場合は「渡した集合の中で」の判定にしかならず（生成側の視野を引き継ぐ。SB-12）、`verified` にしない |
| 件数（「N 件」） | **できない** | 走査にシェルが要る。`density-verify` §2b の検算官（未確立。`count-verifier: prompt-isolated`） |
| 渡していないファイルにある missing | **できない** | 検索ツールが無い。Claude Code の検証官と差が残る部分 |

走査コマンドの出力を渡す形は、**走査コマンド自体の正しさ**（目印の系統の漏れ）を検証官に委ねない——それは §2b の検算官の仕事である。
候補が数十件を超えると 1 ファイル 1 Read で実時間とコンテキストを食うので、ブロックか母集団を分割する。
分母を機械で決められない唯一型・全称型は、GP-16 ルール8 の縮退（別コンテキスト再検証 → 人間サインオフ）へ回す。
検証官が `UNDETERMINED` 等の判定外の値を返したら `CONFIRMED` と読まない（判定できなかった主張として残す）。

**隔離の確かめ方**: **終了コードが 0 の結果だけを使う。** スクリプトは検証の前に、同じ起動条件の別セッションで
探針を走らせ、(a) ワークスペースの外に置いた推測できない値（カナリア）が出力に現れないこと、(b) kiro-cli が拒否を報告したこと、
(c) **原典の既知ファイルの 1 行目を読めたこと**（陽性対照。read の信頼が効いていなければ検証官は何も読めず、読まずに判定した結果が
「隔離できた検証」に化ける）を機械で確かめている。指示テンプレートの `isolation_check` 欄は使わない。

| rc | 意味 | 結果の扱い |
|---|---|---|
| 0 | 探針で隔離を確認し、検証結果を得た | 使う |
| 2 | 前提を満たさない（設定・配置・kiro-cli が V3 に非対応・ソースと仕様リポジトリが入れ子・陽性対照に使える原典ファイルが無い） | 検証していない |
| 3 | 探針で隔離を確認できない（外の値が読めた・拒否の報告が無い・原典を読めない） | 検証していない |
| 4 | 解析対象ソースが変更された（SB-5） | 使わない |
| 5 | kiro-cli が異常終了した | 使わない |
| 6 | 検証本体で拒否された操作がある（検証官が read 以外＝検索やシェルを試みた） | 使わない。原典パスの渡し方を見直すか、縮退へ |
| 7 | 検証本体でツール呼び出しが 0 件、または【原典パス】の件数未満（原典を読まずに／全部は読まずに判定した） | 使わない |

**縮退**: 0 が得られないときは GP-16 ルール8 の縮退（別コンテキスト再検証 → 人間サインオフ）へ倒す。

**この手段で起動できない検証官**:

| 検証官 | 理由 | 起動方法 |
|---|---|---|
| 件数の検算官（`density-verify` §2b） | 走査コマンドの実行にシェルが要る。非対話モードでは `--trust-tools` にコマンド単位の絞り込みが無く（ツール ID 単位。`execute_bash` を信頼すると全コマンドが通る）、`permissions.yaml` の `capability: shell` ルールで絞る経路は未測定 | **未確立。** 段階的縮退（別コンテキスト再検証 → 人間サインオフ）で行い、台帳の notes に `count-verifier: prompt-isolated` と残す |
| レンズ反証者（`spec-adversarial-audit` 手順 2） | `specs/` と code-graph を読むことが任務に含まれる | サブエージェント（隔離は指示文の規律だけ） |
