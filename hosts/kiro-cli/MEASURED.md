# Kiro CLI 実測記録

> **このファイルが `SUPPORT_LEVEL` の根拠である**（GP-107 ルール8）。
> **測ったのは検証官の隔離と skill の読み込みに関わる項目だけ**で、生成パイプライン全体は回していない。
> そのため `SUPPORT_LEVEL=placed-unverified` を名乗る（未測定の項目を「問題なし」と読まない）。
> 設計の全体は `docs/designs/verifier-isolation.md`、測定で踏んだ罠は `dev/developing-the-framework.md` 教訓 63。

**測り方**: フィクスチャの各ファイルに一意のトークンを埋め、検証官の出力とセッション記録に現れるかを見た。
**現れたトークンは漏れの証拠になるが、現れなかったことは漏れていない証明にならない**（判定の多くはモデルの自己申告に基づく）。
**回数は項目ごとに記録していない**（各 1 回以上。判定が揺れた項目は無い）。再測定するときは回数を残すこと。

## 追補 V3-1: 検証官が使えるツールと `--trust-tools` の意味（2026-10-26。kiro-cli 2.34.0・V3・macOS）

> **何を直したか**: 初版は `--trust-tools=read,grep,glob` で起動し、項目 7 に「`grep` / `glob` はワークスペースの外を検索できない」と書いていた。
> 実測の結果は 2 つ: (1) **`grep` / `glob` というツールは V3 に存在しない**。検索の要求はシェルに落ち、シェルは既定で確認待ち＝非対話では拒否される。
> (2) **`read,grep,glob` は 3 つとも実在しないツール ID で、何も信頼していなかった**。ワークスペース内の read が通っていたのは Kiro の
> 既定の許可（`fs_read` は `./**` を自動許可）のおかげである。実在する ID（`read_file`）を信頼すると**境界を問わず承認され、外も読める**。
> `kiro-verify.sh` は拒否行を出力から除いて rc=0 で返していたため、**検索できなかった検証が「隔離できた検証」として台帳に載る** fail-open だった。
> 「外を検索できない」と見えたのは**シェルが非対話で拒否された**ことだった可能性が高い（初版の記録に実ツール名の記録が無いので断定しない）。

**測り方**: 一時ワークスペース（`b.txt` 1 件）とその外のカナリア（`canary.txt`）で `kiro-cli chat --v3 --no-interactive --trust-tools=<名前> "<指示>"` を
起動し、ACP イベント（`--output-format stream-json`）の `tool_call.kind` と `rawInput` で**実際に呼ばれたツール**を見た（モデルの自己申告ではなく呼び出し記録）。
MR レビュー担当者（本体の開発者と別人）が実施。**測定の途中で手元の kiro-cli が 2.33.0 → 2.34.0 に上がった**ため、下表は 2.34.0 で取り直した値である
（2.33.0 で先に取った #1・#4〜#8 相当の結果も同じ向きだったが、版を混ぜないため表には入れない）。

| # | 指示 | `--trust-tools` | 回数 | 呼ばれたツール（`kind` / `rawInput`） | 結果 |
|---|---|---|---|---|---|
| 1 | ワークスペース内の `b.txt` を Read | `read_file` | 1 | `read` / `{"path": ".../ws/b.txt"}` | 成功 |
| 2 | 同上 | `read` | 1 | `read` | 成功 |
| 3 | 同上 | （空） | 1 | `read` | **成功**（何も信頼しなくてもワークスペース内は既定の許可で読める） |
| 4 | 「検索ツールで KVIN を含むファイルを探し、glob 系で `*.txt` を列挙」 | `read_file,read` | **3** | **`execute`** / `rg -l … 'KVIN' .`、`rg --files -g '*.txt'`、`setopt … files=(**/*.txt(N.))` 等 | 3/3 とも `execute`（シェル）が選ばれ、6 呼び出しすべて `[denied]`。`grep` / `glob` という `kind` は 0 件 |
| 5 | 「ツール `grep_search` / `file_search` を使え。無ければ NO_TOOL」 | `read_file,grep_search,file_search,read,grep,glob` | 1 | 呼び出し 0 件。回答 `NO_TOOL` ×2 | 自己申告だが #4 で `execute` 以外が一度も呼ばれなかったことと整合 |
| 6 | 「シェルで `wc -l b.txt`」 | `execute_bash` | 1 | `execute` | **`[denied]`**（公式ドキュメントの ID を信頼しても非対話では通らない。項目 8 と整合） |
| 7 | ワークスペース外の `canary.txt` を Read | （空） | 1 | `read` | **`[denied]`**。値は出力に現れない |

| 10 | 同上 | `zzz_nonexistent` | 1 | `read` | `[denied]`（#8 と同じ。実在しない ID は無視される） |

| 12 | #11 のスクリプトを `--trust-tools=read_file` に書き換えて通す | `read_file` | 1 | 探針でカナリアを読んだ | **rc=3**（カナリアが fail-closed に倒す） |

**帰結**:
- `kiro-verify.sh` は **`--trust-tools=`（何も信頼しない）** で起動する。読めるのは Kiro の既定の許可で通るワークスペース内の read だけで、
  **検証官は渡されたパスの read だけ**で判定する（entry.md §5 に検証できる主張の範囲を書いた）。**`read_file` を信頼してはいけない**（#9・#12）。
- 探針に**陽性対照**（原典の既知ファイルの 1 行目を読めること）を足した。「外を読めない」だけでは read が効いていないことと区別できない。
- 検証本体の `[denied]` は **rc=6**、ツール呼び出し 0 件は **rc=7** で結果を無効にする（出力から除かない）。
- 項目 7 の「`grep` / `glob` は外を検索できない」は「V3 に検索ツールは無く、シェルに落ちた検索は非対話で拒否される」に読み替えた（表のセルも直した）。
- `--trust-tools` に**コマンド単位の絞り込みは無い**（ツール ID 単位。公式ドキュメント）。件数の検算官を隔離して起動する経路は
  `permissions.yaml` の `capability: shell` ルール（未測定）に残る。
- 既定の許可は利用者の `~/.kiro/settings/permissions.yaml` で変わりうる（`fs_read` を全域 allow にすればカナリアが読める→rc=3、ask/deny にすれば陽性対照が落ちる→rc=3）。
  どちらも fail-closed に倒れる。
