# entry.md — Kiro IDE の規範の読ませ方とツール名対応表（GP-107）

根拠はすべて `MEASURED.md`（Kiro IDE 1.4.5 / 2026-10-21）。**CLI には流用しない**（別製品）。

## 1. 規範の読ませ方

| 文書 | 扱い | 根拠 |
|---|---|---|
| ルート `AGENTS.md` | **起動時に自動注入される**（`Included Rules / Workspace-level rule` として）。`CLAUDE.md` 経由ではなく**直接拾う** | A-2a / A-2c-1（3 回） |
| ルート `CLAUDE.md` | **注入されない。** このホストでは不要 | A-2a |
| `specs/AGENTS.md` ／ `spec-extraction/AGENTS.md` | **起動時には読まれない。** ただし**いちど触ると以後のターンで常時ルールに昇格して注入され続ける**（`offset`/`limit` の部分読みでも**ファイル全体**が昇格） | A-2b（4 回） |

**2 つの帰結がある。**

**(a) ルート入口に対象固有の値を書かない（隔離の要件）。** ルート `AGENTS.md` は
**サブエージェントにも注入される**。解析対象パス・`purpose`・スコープをここに書くと、
検証官がそれを持った状態で検証を始める＝`GP-22` の隔離が破れる。
ルートを短く保つ規律は**可読性の話ではなく隔離の要件**である。

**(b) `specs/` だけを開くとルート規範が 0 になる。** Kiro は**親ディレクトリへ遡って
`AGENTS.md` を拾わない**ので、1 つ上の `AGENTS.md` は存在しても注入されない。
`spec-extraction/` へ届くかは **3 分岐**——対話なら承認を経て読める／無人では届かない／
配布単位に無ければ存在しない。

## 2. ツール名対応表

| 役割（抽象） | Kiro IDE でのツール名 |
|---|---|
| サブエージェントを起動する | **`invoke_sub_agent`** |
| ファイルを読む | `read_file` |
| ワークスペースを検索する | `grep_search` / `file_search`（**走査範囲に注意。禁止事項 1**） |
| シェルを実行する | `execute_bash`（**シェルは zsh、道具は BSD**。サブエージェントも同じ。完走試験で実測） |

**シェルの注意**（完走試験で担当が何度も失敗した）: グロブは引用する（`--include='*.jsp'`）・配列添字に見える `$t[` を避ける・BSD grep に `-P` は無い・
`head -0` は使えない。迷ったら `bash -c '…'` で包む。**`timeout` は無い**ので、止まりうる走査は `perl -e 'alarm 120; exec @ARGV' <コマンド>` で包む。

**Windows の場合**（上の表と注意は macOS の実測。以下は 1.4.86 の実運用 1 件からの報告で、`MEASURED.md` の Windows 節に出所を分けて書いてある）:
- シェルは **PowerShell**（ツール名は `execute_pwsh`）。`grep` / `find` などの道具・`gates.sh`・`kiro-ide-verify-check.sh` は **`init.sh` を走らせたのと同じ bash** で使う
  （`gate-config.env` の `SOURCE_PATH` がその bash の形で書かれる。WSL で初期化したなら `/mnt/d/…` で、Git Bash からは解析対象が見つからない）。
  **例外は `kiro-ide-allow.sh`**（承認の置き場所が Windows 側のホームにあるので Git Bash で走らせる。`HOST-SETUP.md` §2）。
- **引用符・`$( )`・日本語のパスを重ねた `bash -c "…"` は Kiro に拒否される**（「could not parse this shell command」）。スクリプトをファイルに書いて `bash <ファイル>` で走らせる。
- PowerShell の `Get-Content` は `-Encoding UTF8` を付けないと UTF-8 が化ける。
- **スクリプトをファイルに書いて `bash <ファイル>` で走らせるときは、BOM なしの UTF-8 で書く**（PowerShell 5 の `Set-Content -Encoding UTF8` は BOM を付け、
  bash がスクリプトの 1 行目を読めなくなる。Windows の完走試験で実測）。
- パスは 2 つの形を使い分ける: **`read_file` などのツールには Windows の形**（`D:\…`）、**bash には bash の形**（`/mnt/d/…`）。
- **`read_file` は Shift_JIS（CP932）のファイルの日本語を化かす**（識別子・数値・行番号は読める）。原典にそうしたファイルがあるなら、
  検証官が原文の文言を照合できないことを Phase 0 で ADR に残す（扱いはプロジェクトで決める）。

## 3. このホスト固有の禁止事項

| # | 禁止・制約 | 理由 |
|---|---|---|
| **1** | **`grep_search` / `file_search` を解析対象（`SOURCE_PATH` 配下）に使わない** | ワークスペース外に対して**エラーではなく 0 件**を返す。「無い」と読むと**分母が静かに空になる**（`GP-2` ルール5 の全走査要求に違反する。`GP-107` ルール6） |
| **2** | **解析対象の走査はシェル（`grep -r` / `find`）で行い、コマンドと件数を成果物に残す** | `enumeration.md`（併用時は `enumeration-<名前>.md` も）の全走査コマンド欄と `G-SCANCMD` / `G-ENUM-SOURCE` がこれを間接的に強制している |
| **3** | **0 件は「無い」ではなく `unknown` として扱う** | 走査範囲外と区別できない（`GP-4` ルール8） |
| **4** | **ルート `AGENTS.md` に解析対象パス・`purpose`・スコープを書かない** | サブエージェントにも注入されるため、隔離が破れる（上記 1-(a)） |
| **5** | **生成物（`02-analysis/` ／ `specs/` ／ `code-graph.md`）を `.kiro/steering/` や エージェントの `resources` に入れない** | `GP-22` の隔離が**静かに**破れる。Kiro では昇格が伝播しないと実測したが、**将来の版や別ホストで成り立つ保証はない** |
| **6** | **検証官の結果は、§5 の確かめ（`kiro-ide-verify-check.sh`）で PASS した行だけを `subagent-isolated` として採用する** | **汎用のサブエージェントは `specs/` を読める（実測 3/3）。** `spec-verifier` の deny も入れ子 `AGENTS.md` の注入は止めない（Phase B の B-2）。止められないので、**記録で確かめて、だめなら採用しない** |
| **7** | **`.kiro/steering/` に `inclusion: always`（または front-matter 無し）の文書を置かない** | 検証官を含むすべてのサブエージェントに注入される（Phase B）。§5 の確かめは**仕様リポジトリの中の文書が検証官に注入されたら FAIL にする**ので、置くと全員が不合格になる |

## 4. 既知の制約

| 項目 | 実測 |
|---|---|
| ゲートの実時間 | `phase4` **4.5 秒**、最長は `all` の **21.9 秒**（全 5 サブコマンド × 3 回）。既定 120 秒で足りる |
| 出力の上限 | 30,000 字超でも**末尾が残る**＝サマリ行は届く。全文はファイルへ退避される |
| 承認 | **何もしないと長時間の作業がダイアログで何度も止まる**（完走試験）。`HOST-SETUP.md` §2 のスクリプトで、ワークスペースの承認ファイルに広い allow を入れる（人が 1 回。リスクは同節）。**2 層**（グローバル `kiroAgent.trustedCommands` ＋ ワークスペース `~/.kiro/workspace-roots/<hash>/permissions.yaml`）。**未承認は黙って無効化されずダイアログで止まる**（fail-closed）。**一度きりの許可は痕跡を残さない** |
| 信頼 | **1.4.5 に信頼ダイアログは無い**（`security.workspace.trust.*` の設定キーも無い） |
| 並列 | 実効 **3.3 倍**。上限 **5**（ハードコード・設定不可）で超過分は透過キュー。**1 応答に並べるサブエージェントは 4 体まで**（完走試験で、それより多い回と文脈の大きい担当で接続の切断が増え、「失敗」と返った担当が動き続けてファイルを書き換えた回もあった。切断は数分待つと戻ることが多い） |
| 呼び出しの順序 | **1 つの応答に並べたツール呼び出しは同時に走る**。ファイルを作るシェルと、そのファイルを渡すサブエージェントを同じ応答に置かない（完走試験で競合した） |
| skill | 配置は**セッションを開く前**に済ませる（提示一覧は開始時のスナップショット）。`/density-verify` は候補一覧に載るが、**選択しても本文は添付されない**（skill 名の文字列だけが届く） |
| 無人実行 | **承認のセットアップ次第**（`HOST-SETUP.md` §2）。原典の Read File はセッションごとに 1 回出ることがある。セットアップはリポジトリ外に残るので `gates.sh` から検査できない |
| 再起動・更新 | 再起動の後、開き直したセッションの記録が置き換わることがある。Kiro は実行中に自動更新されうる（完走試験の途中で版が上がった）。**確かめは検証の直後に行って保存する**（§5）。**版が変わったら**、検証官を 1 体起動して確かめのスクリプトを走らせ、rc と C5 が出ないことを見てから続ける |

## 5. 検証官の隔離（GP-16 ルール2）

**手段**: カスタムエージェント **`spec-verifier`**（`.kiro/agents/spec-verifier.md`。`tools: ["read"]`、仕様リポジトリへの読み取りを**相対パスで** deny）で
起動し、**終わった後にセッション記録で隔離を確かめる**（`spec-extraction/03-audit/kiro-ide-verify-check.sh`）。
deny は自分で読みに行く経路を塞ぐが、**拒否された読み取りでも入れ子 `AGENTS.md` は注入される**（`MEASURED.md` Phase B の B-2）。
止められないので、**記録で確かめて、だめなら採用しない**（設計: `reverse-spec-flow/dev/kiro-ide-verifier-isolation.md`）。

**起動**（バッチごと）:
1. 起動の直前に時刻を取る: `date -u +%Y-%m-%dT%H:%M:%S`
2. `invoke_sub_agent` で **`name: spec-verifier`** を指定し、指示テンプレート（ブロック本文と原典パスだけを埋めたもの）を渡す。
   **長い指示文は `prompt` に直接書かない**（切り詰められる。実測）。指示文はファイルにして `contextFiles` で渡し、`prompt` は
   テンプレートの 1 行目で始まる短い一文にして「添付を読み直さない」と書く（読み直すと原典の外を読んだことになり C3 で不合格になる）。
   **ファイルは前の応答で作る**（同じ応答で作って渡すと届かないことがある）。仕様リポジトリの外（`/tmp` など）に置いてよい（deny に掛からない）。
   **指示文の【原典パス】は絶対パスで書く**（`gate-config.env` の `SOURCE_PATH` を基点にする。検証官は相対パスを使わない。
   相対はワークスペース＝仕様リポジトリを指す）。**仕様書の `path:line` は相対パスのまま**で、書き換えない。
3. **全員が戻ったら、すぐに**確かめ、出力をそのままリポジトリに保存する（完走試験で、再起動でセッション記録が失われ、まだ確かめていない検証官は事後に確かめられなかった）:
   `bash spec-extraction/03-audit/kiro-ide-verify-check.sh --since <1 の時刻> > spec-extraction/03-audit/verify-log/isolation-check-$(date +%Y%m%d-%H%M).txt`
   **Windows（WSL の bash）では**、記録の場所とセッション ID が WSL に届かないので渡す:
   `KIRO_SESSIONS_ROOT=/mnt/<ドライブ>/Users/<ユーザー>/.kiro/sessions bash … --session <セッション ID> --since …`
   （セッション ID は PowerShell の `$env:KIRO_SESSION_ID`。コマンドはファイルに書いて `bash <ファイル>` で走らせる）。
   比べるのはパスの文字列で、大文字小文字を区別する（ドライブ文字だけは揃える）。検証官に渡す【原典パス】は `SOURCE_PATH` と同じ綴りで書く（違うと C3 で不合格になる）。
   **保存した出力が採用の根拠になる**（セッション記録が後で消えても、この出力で確かめた事実は残る）。保存してから集計・台帳に進む。
   記録が大きいと時間がかかる（数十体で 10 分を超えた）。バッチごとに `--since` で絞って走らせる。
4. **応答を集める**: 検証官の応答はセッション記録の `sub_agent_complete` の `response` に残る（ファイルには残らない）。**全員が戻ってから**集める。
   **添付が届かなかった検証官の結果**（`isolation_check` が UNVERIFIED、材料なしの REFUTED）は、確かめが PASS でも採用せず、検証し直す。

**隔離の確かめ方**: **PASS の行の検証官の結果だけを使う**（台帳の `verifier` = `subagent-isolated`）。
行の `block_id=` が検証官の応答の `block_id` である。FAIL の行の結果は**集計にも台帳にも入れず**、検証し直す。
検証官の出力の `isolation_check` は使わない（自己申告で確かめない）。スクリプトは次をすべて満たしたときだけ PASS にする:

| # | 確かめること | 記録のどこを見るか |
|---|---|---|
| C1 | 検証官のテンプレートで起動したサブエージェントが `spec-verifier` である | `messages.jsonl` の `sub_agent_start` |
| C2 | ルートの `AGENTS.md` 以外の仕様リポジトリの文書が検証官に注入されていない | `sub-executions/<id>.jsonl` の `steering_inclusion` |
| C3 | 実際に読んだのは解析対象ソースの配下だけ（`grep_search` / `file_search` / 読み取り以外のツールは使っていない） | 同 `tool_call` のうち拒否されていないもの |
| C4 | 最初のファイル操作がルートの `AGENTS.md` の読み取りで、エージェント定義の deny で拒否された（カナリア） | 同 `tool_call` の `policyDenial.source = subagent-profile` |
| C5 | 記録が想定した形をしている（起動時の注入にルートの `AGENTS.md` がある・完了の記録がある） | 同。**形が変わったら FAIL**（黙って合格にしない） |

| rc | 意味 | 扱い |
|---|---|---|
| 0 | 対象の検証官がすべて PASS | 結果を使う |
| 3 | 1 体以上 FAIL | **PASS の行だけ**使う。FAIL の行のブロックは検証し直す |
| 2 | 前提を満たさない（記録・設定・定義が見つからない・定義に `specs/**` の deny が無い） | 何も確かめていない。理由を直す（定義が壊れていれば `apply-host.sh` で kiro-ide を置き直す） |

**承認**: `HOST-SETUP.md` §2 の `kiro-ide-allow.sh` を人が走らせてあれば、検証官の起動とシェルで止まる回数は大きく減る見込み（**未実測**。完走試験の後に用意した）。
原典の「Read File」がそれでも出たら、**Apply to = This Session、Path = 原典の中のいちばん上の候補**（`**` と All Workspaces は選ばない）。
広く許しても**検証官の仕様リポジトリへの deny は崩れない見込み**（公式文書の記述では deny がどの allow より強い。この組み合わせの実測は無いが、崩れても C4 のカナリアが FAIL にする）。

**実測**（Kiro IDE 1.4.5。`MEASURED.md` の V）: 指示どおりの検証官は 3/3 PASS、仕様リポジトリを読もうとした検証官は 3/3 FAIL（C2）、
deny を持たないエージェントは FAIL（C1）。**相対パスの deny は効く**が、拒否されても入れ子 `AGENTS.md` は注入される（これを C2 が捕まえる）。
確かめは IDE のシェルから走らせても動く。**Windows（1.4.86）**: 実際の記録で検証官 2 体が PASS、記録の写しに原典の外の読み取り・入れ子 `AGENTS.md` の注入を
書き足すとそれぞれ C3・C2 で FAIL（`MEASURED.md` の Windows 節）。

**縮退**（確かめが使えないとき。例: Kiro の更新で記録の形が変わり rc=2・C5 が続く）:
汎用のサブエージェントで起動し、**台帳の `verifier` を `prompt-isolated` にする**（2026-10-22 に決めた扱い β。
`reverse-spec-flow/dev/kiro-ide-verifier-isolation.md` §5）。件数は `rebuild-readiness.md` の「検証手段の内訳」に書く
（台帳と同じ数かを `G-VERIFIER` が見る）。

**この手段で起動できない検証官**: 件数の検算官（`density-verify` §2b）とレンズ反証者（`spec-adversarial-audit` 手順 2）は
汎用のサブエージェントで起動する（隔離は指示文の規律だけ。確かめの対象外で、スクリプトは SKIP と出す）。
検算官は台帳の notes に `count-verifier: prompt-isolated` と残す。
抽出標本の反証者（`spec-adversarial-audit` 手順 3）は `spec-verifier` で起動し、同じ確かめを通す。

**Kiro CLI の手段を流用しない**: `hosts/kiro-cli/` の `kiro-verify.sh` は IDE から呼ぶと `rc=3` で止まる
（ターミナルからは `rc=0`。Phase B の B-6）。**IDE と CLI で境界の挙動も違う**（外への deny は IDE では効き、CLI では無視された）。
